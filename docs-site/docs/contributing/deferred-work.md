# Deferred work

Things that were found, designed or discussed and left for later on purpose. Each entry says why it was left, so it can be judged again rather than rediscovered. Newest sections last.

## Certificates and operators

- **Renewal covers the Secrets the chart names.** The agent and the operator's renewal sidecar renew the client certificates of the telemetry exporters, the receiver's certificate and the mTLS destination's client certificate (and the operator's `renew.extraSecrets`); a certificate in any other Secret is not renewed. The collector's `tls_check` receiver (alpha) can report a mounted certificate's remaining time as a metric, but it travels over the very connection that fails when the certificate has expired, so it complements the server's state rather than replacing it.
- **Gateway stamping and enforcement of the certificate name.** Each cluster's certificate carries `<operator>-export-<cluster>`, but the receiver does not check it, so a certificate proves "some sender of this operator", not which cluster. Checked against collector 0.160.0: it ships no authenticator that reads the client certificate's subject (the contrib extensions are basic auth, bearer token, OIDC, OAuth2 and similar), so enforcing the name needs a different gateway or a custom collector build. Per-sender revocation is the same problem: the receiver trusts the operator's CA as a whole.
- **Full CA rotation.** Per-operator CA keys are sealed under the passphrase in force at creation and are not re-sealed when the passphrase changes; plaintext rows made before a passphrase was set stay plaintext. Re-seal on startup or at reissue.
- **No revocation list.** Revoke and renew only stop new issuance; a running receiver keeps trusting the CA in its Secret until that Secret changes, because it re-reads its client CA when the file changes (`client_ca_file_reload`). The UI text should say so.
- **Regional-operator address reporting**, and **IPv6 kubelet brackets**.
- **Reissue ordering.** Per-sender ledger and audit rows are written before the final audited update; a failure part-way leaves certificates recorded that nobody holds. Write the audit first and the ledger last.
- **Operator CA creation** does two 64 MiB Argon2id derivations with no concurrency cap; seed the CA cache with the issuer returned at creation and run sealing through the same slot semaphore.
- **`/command` and scope edits mint a new certificate every call**, and the ledger list is unbounded. Mint only when the destination changed; paginate; mark ledger rows of revoked operators.
- Smaller: name length is counted in bytes not characters and control characters are accepted; numeric shorthand hosts such as `127.1` pass address validation; the alert-level write is not compare-and-set.

## FUSION

- **Grafana shares an origin with the Ikhnos UI** and renders data that comes from monitored clusters. Serve the pages from a separate origin (the ticket flow already supports a cross-origin hop), or at least default Grafana off.
- **Grafana's datasource proxy** is allowed with write methods; confirm Loki's push and delete endpoints are not reachable through it, or deny `/api/datasources/proxy/` for non-GET.
- **FUSION access tokens outlive their creator's admin role** (up to 365 days); revoke a user's tokens when they lose the role, or check the creator at use.
- **No per-caller fairness** on the shared data client (8 in-flight calls): one token can starve the rest.
- Upstream and Kubernetes error text is returned to API clients; return a generic message and log the detail.
- **Components enabled after first install stay at 0 replicas** under `switch.managed` until FUSION is toggled.
- **Storage cannot be resized with `helm upgrade`** (`volumeClaimTemplates` are immutable) although the values comments say to adjust `storage`.
- The batch size limit counts items, not bytes; large items can exceed the 4 MiB receive limit and be dropped.
- Agent telemetry collectors now have liveness and readiness probes, and the host `filelog` keeps checkpoints in an `emptyDir`, so a container restart no longer leaves a gap in container logs. A replaced pod still starts from the end of each file, so each pod replacement does.
- The central TLS private key is copied into Helm release history by the `lookup` idiom.

## Commands and charts

- **The operator chart file is never offered for download** in the default setup (no registry, no `--chart-ref`): the printed command names `./ikhnos-regional-operator-<v>.tgz` but nothing tells the user to fetch it. Expose it in `info` and add a step.
- Several chart value blocks are dereferenced without a `default` (heartbeat, health, export.queue, export.routes, tls, telemetry.\*). The printed commands now use `--reset-then-reuse-values`, which hides this for upgrades through the product, but Argo CD or Flux users with older stored values can still hit nil-pointer errors. Guard with `dig` and add a render test with each block removed.
- Chart-reference and version logic exists four times on the server and twice in the browser; fold into one helper.
- The server chart's `agentInstall.imageRegistry: "none"` is documented but the binary exits on it; the chart has no `imageDigest` value.
- `kubectl create secret`-style commands in the browser still put a credential in `--from-literal`; move them to the same here-document form the server uses.
- The uninstall command leaves the receiver TLS, receiver auth and heartbeat Secrets behind.

## Found while testing the telemetry path end to end (real collector and Prometheus binaries)

- **Failures are quiet.** (Partly addressed: the operator chart has `selfMetrics.logLevel`; at `debug` the receiver logs every refused handshake with its reason, which at `info` it does not.) A wrong CA, wrong client certificate, wrong server name or a down Prometheus produce only an `info` line "Exporting failed. Will retry" (the cause is in its `error` field); `otelcol_exporter_send_failed_metric_points` stays absent for the 30 minute retry window; the gateway logs nothing for a rejected client certificate; the health check is a plain `GET /`, so readiness stays green with a dead exporter (the agent now reads each collector's export counters and the Pipeline page says so, and it counts a queue that does not drain as failing, so the retry window no longer hides a dead destination from the page). The collectors' own `:8888` metrics are on loopback unless the chart sets them (the central gateway pushes its own to Prometheus; the operator has `selfMetrics.enabled: false`). Enable self metrics by default and show "export failing" in the UI from the operator health.
- **The command that points a cluster at an operator states only the destination.** Rendered with just those flags the agent chart deploys no telemetry workload; nothing is sent until signals are enabled. The screen should say so where the command is shown.
- **An operator address ending in `:4318`** (the OTLP/HTTP port) can never work with the product's gRPC exporters unless a load balancer maps it; warn when one is saved.
- Collector 0.160 logs deprecation warnings for the `otlp`, `otlphttp` and `hostmetrics` component aliases (`otlp_grpc`, `otlp_http`, `host_metrics`); switch the templates before the aliases are removed.
- Fixed in the same pass: FUSION's "waiting for first data" and the starter dashboard read `target_info`, which Prometheus does not write for infrastructure metrics; and series that differed only in an unpromoted resource attribute (container, StatefulSet, DaemonSet, Job, volume) were merged.

## The agent and the local operator

Found while reading the discovery agent against the local operator, and planned in this order. The agent is meant to be the one door between the cluster and the server; these are the places where it is not only that, or where it cannot yet see the local operator well.

- **The agent's identity Role grants `patch` it does not use.** The agent reads its identity Secret and updates it; nothing patches. (The certificate-renewal Roles, the agent's and the regional operator's sidecar's, no longer grant it.) Dropping it is a narrowing with no behaviour change; it is left because the install-time disclosure (`src/lib/types.ts`), the permission reference and the tests that mirror it name `get/update/patch` and should change together with it.
- **The passive cluster-link series, the peer-list API and the iperf3 credential API live in the agent.** The series are in the agent's memory, so they restart at zero whenever the agent is recreated (a change to its telemetry settings recreates it), and they are served from the process that holds the cluster's identity key. The plan is a small separate pod in the local operator's group, with no server credential and no Kubernetes token, that serves the series and both APIs. The agent keeps the namespace-exclusion gate and forwards only the rows it has admitted, plus the config slices the server approves, so the agent stays the cluster's one door. The switch is kept for one release. Done so far: the pod exists as `ikhnos link-hub` (package `internal/linkhub`), with the agent's side (`linkhub.Forwarder`) beside it; the two messages (rows, and the sealed configuration slice) are signed in contexts of their own with a secret only the agent and the hub hold; the hub links neither the Kubernetes client nor the agent (a test holds that); every field of a row is decided as sent or left behind (a test fails for a new one). The agent has the flags that make it forward instead of serve (`--link-hub-url` and `--link-hub-secret-file`; with them it refuses to listen for the links or to hold the prober's or the responders' secrets) and says `link_hub_unreachable` when the hub has not answered for two minutes. The chart has the pod behind `telemetry.clusterLinks.hub` (a Deployment with no ServiceAccount token, its own Secret, a Service for the agent to send to, and a policy that lets only the agent reach it); the Service `ikhnos-agent-link-metrics` keeps its name and selects the hub when the switch is on, so the collector, the prober and the responders are unchanged, and the agent then mounts neither the prober's nor the responders' secret. Still to do: flip the default after a release in which it has run on real clusters, then remove the agent's own listener; the series still start at zero when the hub restarts (the hub is smaller than the agent and is not recreated by telemetry changes, but its state is in memory).
- **The agent's readiness decides whether the flow-report and link-series Services have a pod behind them.** After ten minutes without the server the agent is unready, and the link series disappear with it although the cluster is fine. The move above removes this for the link series.
- **What an intent declares is compared with what is installed, not with what runs.** The Pipeline page now lists the differences between the intent and the agent's report (signals, the energy and accelerator sources, the destination per signal type, the application scope). Both sides are release values. A destination that names an operator is matched the way the server's command chooses its address: the one the sender picked, else the address recorded for the operator (for the central operator, where FUSION is exposed), else its name inside its own cluster; the name stays accepted. The page takes the recorded address from the operator list it already loads, so a collector in another cluster that dials the central operator's public address is not shown as different. Still open: the intent has no time of its last change (an `updated_at` column set by the three update calls would let the page say "asked 12 min ago, not applied yet" instead of naming both causes); tags, extra processors and the protocol and TLS of a route are not reported by the agent, so they are not compared; and the running configuration is not read. The collectors' pods carry `checksum/config` and nobody reads it. The server cannot compute the expected value (it embeds the chart and never renders it), so the running config has to come through the controller, which has the Helm engine; that part waits until the controller has run on a cluster with nodes.
- **Export health.** Fixed: its change detection ignored the receiver and source counters and so sent a message at every reading that had data; the rows of an exporter that was removed were never dropped; the cluster collector was counted twice; and the queue depth was read but not reported (it now is, with the capacity, the items the queue refused and the collector restarts). Still open: there is no expected pod count, so a DaemonSet pod that is not Ready makes "2 pods read" look healthy on three nodes when no controller keeps the release; \"unreadable\" merges four causes (a NetworkPolicy, a failed name lookup, collectors that are down, a wrong port); and a part of the pod that only the source-health port serves can fail without the pod count saying so. The names the agent carries in Go are held against the rendered chart by `exporthealth_contract_test.go`, which has to stay green before the component aliases are renamed.
- **The flow and node-probe receivers.** Fixed: below tier 2 the flow pipeline is paused (it answers the collectors and takes nothing in, so nothing is held for a flush that never comes and the collectors slow down); a source address that sends more than a collector does (more than 15 at once, then one every 2 seconds) is answered 429 before its body is read; flow reports are signed in a context of their own (`ikhnos-flow-v1`), the node probe's keep the default, and the agent refuses to start when the probe, flow, link-peers and iperf secrets are not all different; the wire constants live in `internal/flow/wire`, so the collector no longer links the Kubernetes client (a test holds that). One thing to know when upgrading: a flow collector of the previous release signs in the old context, so during the rollout the new agent answers it 401 until its pod is replaced, and the reports of those minutes are lost. Still open: the limit is per address, so collectors behind one NAT address share a bucket (nothing in the chart does that today); and the reports of a source that is limited are not counted anywhere the Pipeline page can see (they are logged once a minute).
